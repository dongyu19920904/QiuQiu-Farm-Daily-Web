# 秋秋农场日报：内容与农场视觉优化方案

日期：2026-10-08（Asia/Shanghai）。范围：独立农业日报前端与生成器；原 AI 日报只读。

## 1. 现状与原因

当前前端为 Hugo 0.147.9 + Hextra；生成器为 Node + Folo/公开 RSS + Anthropic 接口，GitHub Actions 构建 Cloudflare Pages。日报路由、全文搜索、往期、主题切换和静态 SEO 已存在，继续保留。

实查发现：采集按科技新闻先入队，写稿分数又给 AI 100 分、园艺 70 分；科技内容在两层选择中占优。主题栏目最低数量为零，模型可以把素材全塞进 TOP10。增加订阅数量不能自动解决选稿失衡。一次混合大量原文写全篇还容易串用地区、温度、数字。当前媒体通过关键词套用两张资料照与两张原创图解，不是逐条原新闻配图。

原 AI 日报的长处是短结论、自然来源链接、重点高亮、摘要、焦点及独立的小栏目。继承这些阅读方式，不复制账号导购或为凑栏目写虚假新闻。

## 2. 日报结构与选稿

“模块增加”落实为日报内栏目，不重新开启此前停用的雷达、时间线等独立业务页。

| 栏目 | 素材和用途 | 目标 |
| --- | --- | --- |
| 今日摘要 | 三句概括实际正文，兼顾家庭行动与农业 AI | 3 句 |
| 今日焦点 TOP10 | 真新闻、当季实用读物、作者实践混合选读；知识明确标识 | 最多 10 条；其中实用内容优先至少 4 条，科技不包场 |
| 菜园实用课 | 播种、容器、光照、水肥、土壤等有条件的方法 | 2–3 条 |
| 田园实践 / 社媒精选 | 真实作者与实做记录，保留地区和日期 | 2–3 条 |
| 智慧农场与新工具 | AI、机器人、软件、灌溉工具：用途、规模和限制 | 1–2 条 |
| 农业研究 / 行业观察 | 有依据的研究结果或农业变化；区别目标与实现 | 各 0–2 条 |
| 田园趣闻 | 有具体事实的有趣发现，不编段子 | 0–1 条 |
| 今日小任务 / 相关问题 | 来自本期推广资料的短问答或低风险观察任务 | 1 条 |

有材料才开栏目，预计 16–20 条独立内容、6–8 个有效栏目；这不是每天凑数承诺。正文使用连续标题和来源链接，避免同 URL 或事件在多个栏目重复。一家发布者上限 3 条。已发布事件七日去重；常青知识只能明确标为知识，不能改日期冒充新闻。

采集先为实践、知识、新闻分别预留容量，再按时间和相关性补位。核心受众是想种菜、喜欢田园生活的人；高投入商业设备标清适用规模，不硬写成家庭教程。外国地区的季节、光温和品种限制不可删除。食品安全与农药不能凭模型补配方。

## 3. 写作与质量控制

新增显式栏目选稿清单，模型逐组接收各条指定原文及指定栏目，避免自行挪用素材。保留原项目的写作内核、摘要组装、发表格式检查、独立事实审核、隔离发布和失败保留线上逻辑。去掉上次试验中针对某一天的硬编码植物事实。

各条只使用自己的来源；标题、摘要也核对状态与条件。采集、原文、选稿、模型用量和审稿结果保存证据。实际生成完整一期，逐条读稿核对链接；失败针对具体条目修复，再检查整期。未审核稿不发布。自动审稿不代替人工读稿。

## 4. 原新闻配图

禁止关键词匹配图库、AI 图片和程序绘制的新闻图解。图片必须同时满足：本条来源 URL 精确匹配、原页面实际含该图片、来源与署名清楚、有允许使用的依据、图片可加载。原文无合格图则不放。

优先明确授权的农技机构原文照片；采集器记录原图 URL、来源文章 URL、许可证/引用依据和检查时间，禁止模型发明 URL。文章用现有 shortcode 与媒体清单显示原图及署名，不改变搜索数据结构。历史中的不对应资料图及原创新闻图解移除，事实正文、日期、路由不变，更新媒体修订回执。UI 场景与小图标单独标为原创装饰，不是新闻图片。

## 5. QQ 农场视觉的核心与改法

核心是“俯视小农场场景 + 生长中的作物 + 木质游戏控件 + 可辨认的入口 + 明快且有厚度的图形”，不是只把底色改绿。增加有层次的天空、远山、木屋、栅栏和等角菜畦；在招牌、栏目入口与标题中统一木纹、铆钉、圆角、立体边缘和作物图标。使用原创 SVG/CSS，避免搬运版权不明的腾讯素材。

标题使用许可清楚的圆润中文字体，正文继续现有中文无衬线字体、17px 或以上。首页从真实文章标题生成栏目入口，跳转现有正文锚点；不虚构金币、经验、商店或可玩按钮。场景仅作氛围，不挡文字、不影响选择复制。夜间保持文字对比，手机缩小装饰而保留触控面积。性能以本地轻量 SVG、字体子集和现有 CSS 覆盖为主。

## 6. 修改边界与顺序

1. 保存本方案与状态；合并独立新项目正常生产回执，保留旧质量试验记录。
2. 改生成器采集预算、栏目清单和写作提示；新增来源精确配图检查及相应测试。
3. 增强前端 farm-theme、原创场景、标题字体和正文栏目入口；公共搜索、往期和 Footer 统一。
4. 当日采集与真实模型生成、整期原文读稿；修复失败，才接受内容。
5. 移除旧错误配图并核对历史事实文本不变；更新回执、搜索数据。
6. 运行 Node 测试、Hugo、静态 SEO 与浏览器桌面/平板/390px、日夜与搜索回归。
7. 推送独立两仓库，执行现有农业 Pages 发布链；打开真实域名验证文章、图、锚点、搜索与手机版。记录部署和回滚方法。

## 7. 验收与风险

- 与旧稿对比：实用/作者实践不再被科技挤走，有真实材料的独立栏目确实出现；所有实质性声明可追溯。
- 每张新闻图有精确文章关系和使用依据；无来源图不补假图。
- 首页明显呈现农场场景与木牌入口；正文、历史、搜索、主题、手机及 SEO 保留。
- 构建测试、真实生成及部署三类回执分别记录，不能互相替代。
- 风险：来源停更、网络/付费墙、图片版权、模型串事实、单日素材不足；分别排除/记录，不购买服务或发布假稿。
- 外部费用沿用独立模型和既有 Pages；只记录真实调用回执，未查询到余额不估造余额。原 AI 项目、旧 Cron/Worker/KV/DNS 不变。
- 回滚：新仓库恢复上一个已验证内容及前端提交，通过现有 force_deploy 发布；不 reset 旧项目、不删历史数据。
